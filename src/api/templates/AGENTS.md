# templates

Jinja2 pages rendered by `../routers/pages.py` and `../auth_routes.py`. `base.html` holds the document shell, the top bar (nav, with an Admin link for the users `is_admin` names; Sync button; Feedback button; theme toggle; user links), the footer (Privacy and source links on every page, and for a signed-in user a Send feedback button, the way to the feedback modal on a phone, where the top bar has no room for it), the feedback modal that `../static/js/feedback.js` drives, and the `data-*` attributes on `<body>` that the page modules read. Visitors get a top bar with Courses, Log in and Sign up. Pages fill `title`, `meta` (a search description), `styles`, `content` and `scripts` blocks; auth pages also set `page_class` to `page-narrow`.

- `dashboard.html`, `streams.html` (one activity), `index.html` (activities list and workout library), `training_calendar.html`, `profile.html` (ends with the Delete account card and its modal, which `pages/profile-account.js` drives), `pacing.html` (one race's pacing plan, with the print-only pace band), `admin.html` (sign-ups by week and the feedback notes, for admins): logged-in pages. Their markup is placeholders that `../static/js/pages/*.js` fill. `data-athlete-id` is `user.athlete_id`, so the pages work for a user who only imports files; `strava_athlete_id` in a template only decides whether Strava controls (Sync button, connect prompt, Strava card) show; the dashboard's connect prompt starts hidden, and `pages/dashboard.js` shows it only while the user has no activities.
- `home.html`, `courses.html`, `course.html`, `course_missing.html`: the public pages from `../routers/pages.py` and `../routers/courses.py`, with no account: the home page with the race search, the course list, one course with its pacing plan (the pacing page's element ids, so `../static/js/pacing-view.js` draws both), and the 404 or 503 for a course that cannot be shown.
- `privacy.html`: the privacy page, public, plain text in one narrow column (`css/pages/privacy.css`). Every claim on it is checked against the code; change it when the data the app stores or the services it talks to change.
- `login.html`, `register.html`, `setup.html` (first race; `pages/setup.js` turns its name field into the race search and fills the hidden catalog fields), `strava_auth.html`: the sign-up flow. Plain form posts; `register.html` has a small inline module that converts height and weight to meters and kilograms before submit.
- `forgot_password.html`, `reset_password.html`: the emailed password reset. Plain form posts; the reset token rides in a hidden field.
- `email/`: the HTML emails, not pages; see its own AGENTS.md.

`coros_enabled` (a global set in `../main.py`) leaves the COROS card out of `profile.html` and the Recovery card out of `dashboard.html` when COROS is switched off; `is_admin` (set there too) decides the Admin link in `base.html`.

Keep markup here and behaviour in the page modules; the only inline script is the theme bootstrap in `base.html` and the unit conversion in `register.html`.
