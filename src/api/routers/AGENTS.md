# routers

One `APIRouter` per concern, all mounted by `../main.py`. Each router does the session check through `get_current_user` (API) or `get_current_user_from_session` (pages) from `../auth_routes.py`, talks to Postgres through `SessionLocal` and to the DuckDB warehouse through `get_db_connection` in `../deps.py`.

- `pages.py`: the server-rendered pages (`/dashboard`, `/training-calendar`, `/warehouse`, `/workout_streams/{id}`, `/profile`, `/races/{id}/pacing`, `/privacy`, which needs no login, and `/admin` for the users in `ADMIN_EMAILS`, a 404 for everyone else). Markup only; data comes from the API routers below. The activity page hides the Strava link for imported activities. `/` is the dashboard for a signed-in runner and `home.html` for everyone else, with the biggest races of the course library.
- `courses.py`: the public course pages, no account needed. `GET /api/courses` lists the course library's courses biggest first in the shape of the race catalog; `GET /api/courses/{race}/{event}/pacing?goal&strategy&unit` is the split plan for any goal over one course at its own distance (`pacing.plan_payload` and `pacing.checked_goal`, so it answers like the race pacing endpoint; 404 unknown course, 503 no library, 502 unreadable file). `/courses` and `/courses/{race}/{event}` render the list and the course page server-side so search engines see them (`course_missing.html` for 404 and 503); `/sitemap.xml` and `/robots.txt` use `HOST_URL`.
- `activities.py`: synced and imported activities: list (each row carries `structure_kind` and `structure_checked` from the structure pass), per-user list, detail, streams, laps (the watch's splits), detected intervals (`GET /api/activities/{id}/intervals`, with `checked` and `pending` telling a run not analysed yet from one with nothing found), effectiveness, delete (`delete_activity_rows`: the tables in `src.pipeline.ACTIVITY_CHILD_TABLES`, then `dim_activity`).
- `imports.py`: `POST /api/activities/import`, multipart FIT/GPX upload (up to 20 files, 25 MB each); returns one result per file (`imported`, `skipped` with the reason, or `error`) and `completed`, the number of planned sessions the new activities marked done. The work is in `../services/imports.py`.
- `sync.py`: start a background Strava sync and read its progress (`src.api.services.sync`). `start_sync_for(user)` is the one place that builds a user's sync job; the webhook uses it too. `record_sync_result` stores the new token and then marks matching planned sessions done (`services/plan_match.py`).
- `strava_webhook.py`: Strava's push subscription at `/api/strava/webhook/{token}`, where the token is `STRAVA_WEBHOOK_VERIFY_TOKEN`; any other path is a 404, because Strava does not sign events. `GET` answers the subscription handshake; `POST` takes activity create/update (queue a sync), delete (remove from the warehouse) and athlete deauthorization events. `scripts/strava_webhook.py create <site>` registers the subscription with the token in the path.
- `workouts.py`: the workout library CRUD.
- `analytics.py`: training status (`/status`: the load model's numbers from `../services/metrics.py`, with `acwr_ready` saying whether the history is long enough for the acute:chronic ratio), VO2 max, pace zones, dashboard analytics (HR zones, time by type, weekly volume), race predictions if the runner raced today (`/api/predictions`, from `../services/predictions.py`: each row's time, range, the effort it came from, Tanda's training time for the marathon and the course factor of a race with a course; each upcoming race's goal read by `src.pacing.parse_goal` for its distance; the VDOT ceiling), aerobic efficiency on easy runs (`/api/efficiency`), personal records (`/api/records`).
- `races.py`: races CRUD, and the race catalog. `GET /api/race-catalog` lists the events of `../services/course_library.py` whose distance is within `LENGTH_TOLERANCE` of a length this app plans for (`race_length_for`), biggest first, with `has_course`; 503 when the library cannot be read. `POST /api/races/{user_id}` takes an optional `course` (`{race, event}` of a catalog event) and stores its course with the race through `course_library.attach`, answering the course summary or null; the race list carries `has_course`.
- `profile.py`: profile updates and `GET /api/hr-profile/{user_id}` (resting and max heart rate in use, and where they come from; `detected_max_hr` is null without heart rate data, `default_max_hr` is the fallback). A changed heart rate profile queues a metrics recompute, after any job already running. `DELETE /api/account` with the password in the body deletes the signed-in user and all their data through `../services/account.py` and clears the session; 400 for a wrong password, 409 while a sync or recompute runs for them.
- `plan.py`: training plan entries CRUD; `GET /api/projection/{user_id}`: fitness, fatigue and form stepped forward along the planned sessions (load per session from the athlete's TRIMP per kilometre scaled by workout type), with upcoming race dates; a race day carries the values of its morning, before the race's own load; `POST /api/training-plan/{user_id}/build`: fills the calendar from tomorrow to a race with entries from `src/plan_builder.py`, starting from the last four weeks of run volume in the warehouse unless the body gives a weekly distance.
- `digest.py`: weekly digest email settings (`GET`/`POST /api/digest/{user_id}`), `GET .../preview` for the subject, text and HTML the user would get, and `POST .../send` to send it now.
- `coros.py`: the COROS link: `GET /api/coros/{user_id}` status, `POST .../link` (logs in with email and password, keeps only the token, pulls a year of nights), `POST .../sync`, `DELETE /api/coros/{user_id}`, `GET /api/recovery/{user_id}` with the nightly HRV, resting heart rate and time in bed for the dashboard, `GET /api/readiness/{user_id}`: today's Go / Normal / Easy / Rest call from this morning's energy and its trend, with the reasons and a hint when today's planned session is hard, and `GET /api/energy/{user_id}?days=7` (1 to 14): the energy curve hour by hour with the nights that charged it, the activities that drained it and today's call (`services/readiness.energy_for`). Both answer `{"available": false}` without COROS nights. `../main.py` mounts this router only when `COROS_ENABLED` is not `false`, so every one of these routes answers 404 on an install with COROS switched off.
- `pacing.py`: `GET /api/races/{race_id}/pacing?goal&strategy&unit` builds the split plan from `src/pacing.py` (goal from the query, else the race, else the predictions card's time for the race over its course (`../services/predictions.py`)). Goals are read by `parse_goal` for the race distance: a typed or race goal that is not a plausible time answers 400 with the allowed finish times and paces (`checked_goal`), and a race goal that is not a clock time at all (such as "finish") gives way to the prediction. `POST`/`DELETE /api/races/{race_id}/course` store or drop the course GPX on the race. `plan_payload` builds the plan that both this endpoint and the public course pages answer with. `GET /api/races/{race_id}/course-library` lists the courses of `../services/course_library.py` whose race distance is within `LENGTH_TOLERANCE` of the race's, by name, with only the `LIBRARY_FIELDS`; `POST /api/races/{race_id}/course/library` with `{race, event}` stores one of them through `save_course`, the same parse and store as an upload. Both answer 503 when the library cannot be read.
- `feedback.py`: `POST /api/feedback` stores a note from the Feedback button: `message` (up to 4000 characters; blank refused with 400), `page` (the path it was written on) and `contact_ok`.
- `admin.py`: `GET /api/admin/stats` for the admin page, through `get_admin` (404 unless the user is in `ADMIN_EMAILS`): the sign-up cohorts and totals from `../services/admin.py` and the latest 50 feedback notes.
- `insights.py`: `GET /api/insights/{user_id}?unit=mi|km`: the What to work on notes from `../services/insights.py` for the signed-in user (403 for anyone else, 400 for another unit).

A new endpoint goes in the router that owns its data; a new concern gets a new file here and one `include_router` line in `main.py`.
