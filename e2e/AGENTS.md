# e2e

Browser tests against the real app, run by the `e2e` CI job before every deploy and kept out of `pytest`'s default collection (`testpaths` is `tests/`).

- `conftest.py`: session fixtures. `database` drops and recreates the public schema of `E2E_DATABASE_URL`, then runs Alembic. `fake_strava` serves `fake_strava.py` in a thread. `running_app` starts uvicorn in a subprocess with a temporary DuckDB warehouse and a temp working directory; `app_server` is that with `STRAVA_API_BASE`, `COROS_API_BASE` and `RACE_COURSES_URL` pointing at the fakes, and `app_without_coros` a second one on the same database with `COROS_ENABLED=false`. `registered_user` signs up through the real form and links the fake athlete the way the OAuth callback would. `page` collects console and page errors and fails the test if any appear.
  `running_app` sets the mail, model-key and `APP_URL` settings (`BLANK_SETTINGS`) to empty: the app reads the repo's `.env` wherever it runs, but never over a variable that is already set.
  A console 404 is expected only from a data endpoint (`DATA_PATHS`, matched on the message's URL); a 404 for a page, script or icon fails the test.
  A test that expects another error status takes that one entry out of `page.problems` itself, as the pacing test does for a refused goal's 400.
- `fake_strava.py`: token, athlete, activity list (paged, honouring `after`), streams and laps endpoints, with Strava-sized ids past 32 bits. By default three synthetic 40-minute runs; `synthetic_runs(count, span_days)` makes a varied history (easy, long, tempo, interval and race runs with streams that agree with each summary and per-mile laps) for `../scripts/demo.py`.
- `fake_coros.py`: the Training Hub login, dashboard and dayDetail endpoints with synthetic nights (14 by default, any count for the demo) and no sleep duration, as in the real API; the app reaches it through `COROS_API_BASE`.
- `fake_courses.py`: the race-courses dataset: an index with two half marathon courses (one `warn`), a marathon course and a half with no course file, and the courses' GPX files (21.1 km with one 40 m hill); the app reaches it through `RACE_COURSES_URL`.
- `test_flows.py`: sign-up to the Strava prompt (the first race picked from the race search, with its course map), the profile race search picking with the keyboard and by click (a race without a course map and one with), dashboard empty states, a sync from the button with the progress panel and the filled dashboard, every page rendering, calendar entry add/edit/delete, a heart rate profile change triggering a recompute, Build plan filling the calendar to race day, planned distances following the km/mi switch on the dashboard and the calendar (text that is not a distance, "45 min", stays as typed and out of the month's total), the weekly digest preview and switch, linking COROS and the recovery card with its energy number and curve, the pacing page building splits for a race with a goal (pace and split time the same on every whole mile, a typed 1:45 read as 1 h 45 min, 0:30:00 refused with no pace band), **Find course** listing only the library's halves with a course file, searching them by city, and **Use** giving the plan the course's profile, the structure card saying nothing was found for the fake runs (a ten-minute fast block is neither kind), the Activities page's name search, type filter, sorting, delete and **Show more** over a long history, a sync marking a matching planned run done, a user without Strava importing a GPX file on the Activities page (then the repeat skipped, and the run on the dashboard), COROS switched off leaving out the cards and the routes, the privacy page signed out (and its links in the footer and on the login page), and a throwaway user deleting their account from the profile: signed up through the real form with an imported run, a wrong password refused in the modal, then `/login` with the notice and the old password refused. Tests run in file order; the sync test fills the warehouse the later tests read.
  Tests that need a state the fakes do not give serve it through `page.route`: a held or failed heart rate profile, a recompute already done at the first read, digest settings that do not load, a run served as a ride for its splits, a run the structure pass has not looked at and one it never looks at, and 120 more activities for the Activities page (its delete is answered there too, so the warehouse keeps every run).
  Others check the fitness chart: no empty state after the first sync, the race label inside the chart, and the planned values on race day at its right edge.
- `test_layout.py`: every logged-in page at 390 and 360 px with touch emulation: no sideways scroll, the nav links and Sync button on screen, and no chart axis label cut off or running into its neighbour.
  pytest collects files by name, so it runs after `test_flows.py` and lays out the data those tests created.

Run locally: `E2E_DATABASE_URL=postgresql://user:pass@host/db pytest e2e -q` with `playwright install chromium` done once.
