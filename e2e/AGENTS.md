# e2e

Browser tests against the real app, run by the `e2e` CI job before every deploy and kept out of `pytest`'s default collection (`testpaths` is `tests/`).

- `conftest.py`: session fixtures. `database` drops and recreates the public schema of `E2E_DATABASE_URL`, then runs Alembic. `fake_strava` serves `fake_strava.py` in a thread. `running_app` starts uvicorn in a subprocess with a temporary DuckDB warehouse and a temp working directory; `app_server` is that with `STRAVA_API_BASE` and `COROS_API_BASE` pointing at the fakes, and `app_without_coros` a second one on the same database with `COROS_ENABLED=false`. `registered_user` signs up through the real form and links the fake athlete the way the OAuth callback would. `page` collects console and page errors and fails the test if any appear.
  `running_app` sets the mail, model-key and `APP_URL` settings (`BLANK_SETTINGS`) to empty: the app reads the repo's `.env` wherever it runs, but never over a variable that is already set.
  A console 404 is expected only from a data endpoint (`DATA_PATHS`, matched on the message's URL); a 404 for a page, script or icon fails the test.
- `fake_strava.py`: token, athlete, activity list (paged, honouring `after`), streams and laps endpoints, with Strava-sized ids past 32 bits. By default three synthetic 40-minute runs; `synthetic_runs(count, span_days)` makes a varied history (easy, long, tempo, interval and race runs with streams that agree with each summary and per-mile laps) for `../scripts/demo.py`.
- `fake_coros.py`: the Training Hub login, dashboard and dayDetail endpoints with synthetic nights (14 by default, any count for the demo) and no sleep duration, as in the real API; the app reaches it through `COROS_API_BASE`.
- `test_flows.py`: sign-up to the Strava prompt, dashboard empty states, a sync from the button with the progress panel and the filled dashboard, every page rendering, calendar entry add/edit/delete, a heart rate profile change triggering a recompute, Build plan filling the calendar to race day, the weekly digest preview and switch, linking COROS and the recovery card, the pacing page building splits for a race with a goal, the structure card staying hidden for the fake runs (a ten-minute fast block is neither kind), a sync marking a matching planned run done, a user without Strava importing a GPX file on the Activities page (then the repeat skipped, and the run on the dashboard), and COROS switched off leaving out the cards and the routes. Tests run in file order; the sync test fills the warehouse the later tests read.
  Tests that need a state the fakes do not give serve it through `page.route`: a held or failed heart rate profile, a recompute already done at the first read, digest settings that do not load, and a run served as a ride for its splits.
  Others check the fitness chart: no empty state after the first sync, the race label inside the chart, and the planned values on race day at its right edge.

Run locally: `E2E_DATABASE_URL=postgresql://user:pass@host/db pytest e2e -q` with `playwright install chromium` done once.
